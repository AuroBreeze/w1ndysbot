# KernelActivity

面向技术学习群的任务、订阅与群外活跃度模块。群成员查看任务、历史、详情、进度，或接受、完成、订阅任务时，都会刷新该成员在任务所属群的活跃度。

## 开关

- 群内发送 `KA`：开启或关闭当前群任务功能（群管理员或系统管理员）。
- 私聊发送 `KA`：开启或关闭私聊功能（系统管理员）。
- 发送 `KAmenu`：查看命令菜单。

## 发布任务

群管理员或系统管理员在群内发送：

```text
发布任务
标题：阅读 Linux 调度器代码
截止：7
内容：阅读 kernel/sched/core.c，整理主要入口和调用链。
```

`截止` 是从发布时间开始计算的整数天数；`0` 或省略表示长期任务。数据库保存固定截止时间，每次查看时动态计算剩余天数、小时或分钟。

任务说明较长时可以使用 `详情` 或 `任务详情`，它们都是 `内容` 的别名。详情字段后的多行文字、空行、编号列表、代码路径和链接会原样保存，例如：

```text
发布任务
标题：实现早期串口输出
截止：14
详情：目标：在内核启动早期输出日志。

要求：
1. 阅读 arch/loongarch/boot/boot.c
2. 实现 putchar 与 puts
3. 提交代码和设计说明

参考：https://example.com/kernel-uart
```

除了 QQ 单条消息本身的长度限制，模块不会主动截断任务详情。修改任务时也可以使用 `内容：`、`详情：` 或 `任务详情：` 提交多行说明。

发布成功后机器人会在群内 `@全体成员`。这条正式任务公告不会自动撤回，会作为群内长期可见的任务记录保留；其他查询和操作提示仍按原有规则处理。

快捷格式：

```text
发布任务 7 阅读 Linux 调度器代码
```

## 修改任务

```text
修改任务 K-20260916-001
标题：新的标题
截止：10
内容：新的任务内容
```

只修改填写的字段。修改 `截止` 时从修改时刻重新计算；`截止：0` 改为长期任务。每次修改都会增加版本并保存修改记录。

## 成员命令

```text
当前任务
历史任务 [页码]
任务详情 任务编号
任务进度 任务编号
任务成员 任务编号
接受任务 任务编号
完成任务 任务编号 [说明或链接]
取消完成 任务编号
我的任务
订阅任务
取消订阅
刷新活跃
我的活跃度
```

任务采用信任机制，发送 `完成任务` 后立即计为完成，不需要审核。超过截止时间但尚未关闭的任务允许补交。

`历史任务` 表示本群完整的任务发布历史，因此会同时显示进行中、已截止和已关闭的任务；`当前任务` 只显示尚未截止且未关闭的任务。

任务统计中的“接受总数”是累计参与人数。成员完成任务后只会从“进行中”转为“已完成”，不会从“接受总数”中减少。

## 管理命令

```text
关闭任务 任务编号
重新开启任务 任务编号
任务修改记录 任务编号
```

## 私聊命令

私聊功能开启后，群成员可以使用：

```text
订阅任务 群号
取消订阅 群号
我的订阅
设置默认群 群号
我的默认群
刷新活跃 群号
我的活跃度 群号
当前任务 群号
历史任务 群号
任务详情 任务编号
接受任务 任务编号
完成任务 任务编号 [说明或链接]
```

私聊操作会检查用户是否仍在目标群，以及目标群是否开启了本模块。群成员列表缓存需要由核心群成员列表功能正常更新。

第一次订阅任务群时，该群会自动成为用户的默认群。设置默认群后，`当前任务`、`历史任务`、`刷新活跃`、`我的活跃度`、`订阅任务` 和 `取消订阅` 可以省略群号。取消默认群的订阅时，系统会自动选择最早仍在订阅的群作为新默认群；没有其他订阅时清空默认群。

## 数据

数据库位于 `data/KernelActivity/kernel_activity.db`，保存任务、修改记录、完成记录、查看记录、订阅关系和活跃时间。`GroupManager` 的未活跃扫描会取 NapCat 最后发言时间与本模块最后活跃时间中的较新值。

## 测试

从仓库根目录运行：

```powershell
cd app
uv run python -m unittest discover -s modules/KernelActivity/tests -v
```

测试使用临时 SQLite 数据库，不会写入正式任务数据。
